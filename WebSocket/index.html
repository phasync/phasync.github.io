    WebSocket Class

    A WebSocket connection (RFC 6455), server side.

    Description

    class WebSocket extends ProtocolUpgrade implements \IteratorAggregate, \Traversable
    return WebSocket::from($request, function (WebSocket $ws) {
    $ws->onMessage->listen(function (string $data) {      // inbound: events
        Swerve::publish('chat', $data);
    });
    foreach (Swerve::subscribe('chat') as $out) {         // outbound: plain sequential code
        if ('end' === $out) {
            return;                                       // returning closes the socket (1000)
        }
        $ws->send($out);
    }
});

    The callback runs in a coroutine of its own after the handshake; the connection closes when it returns (1000), or throws (1011, and swerve logs the exception). end() closes it early. A request that is not a WebSocket handshake is answered 426 or 400.

    The connection is read all the time, also when the callback only sends: pings from the client are answered, and when the client leaves the callback is cancelled, so the loop above ends with its client. A message goes to the $onMessage listeners, one at a time, in the order they arrived: a slow listener holds back the reading. The server pings every connection every PING_INTERVAL seconds, from one coroutine for all of them, so proxies don't close a quiet one.

    The pull style is the alternative to $onMessage, and the two don't mix: receive() throws while $onMessage has listeners.

    foreach ($ws as $message) {               // ends when the connection closes
    $ws->send("echo: $message");
}

    send() and end() may be called from any coroutine.

    Defined in Swerve\Http\WebSocket, package phasync/swerve.

    Constants

    MAX_MESSAGE = 1048576
    The largest message received; a larger one closes the connection with 1009.
    PING_INTERVAL = 15.0
    Seconds between the pings the server sends to every open connection.
    INBOX = 64
    Messages received and not yet taken by receive(); the reader waits while there are INBOX.

    Properties

    $onMessage readonly Event
    Called with (string $data, bool $binary) for each text or binary message received.
    $onClose readonly Event
    Called once with (int $code, string $reason) when the connection has ended, whichever side ended it.

    Methods

    • WebSocket::receive The next text or binary message, or null once the connection is closed.
    • WebSocket::getIterator The messages received, until the connection closes: foreach ($ws as $message).
    • WebSocket::isBinary Whether the message receive() returned last was binary, rather than text.
    • WebSocket::send Send a text message; nothing happens once the connection is closed.
    • WebSocket::sendBinary Send a binary message; nothing happens once the connection is closed.
    • WebSocket::end Close the connection: send a close frame with $code and $reason, once.
    • WebSocket::isClosed Whether the connection is closed: end() was called, the client said goodbye, or the connection ended.

    See also

    • ProtocolUpgrade A connection that switches from HTTP to another protocol (RFC 9110, section 7.8): the base of WebSocket, and of any protocol of your own.
    • Swerve::publish Send a message to every subscriber of $topic, in every worker process of this swerve, this one included.
    • Swerve::subscribe Receive what is published to $topic from now on.
