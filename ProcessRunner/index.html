    ProcessRunner Class

    The implementation behind Process::run(): starts a child process and controls it.

    Description

    final class ProcessRunner implements ProcessInterface

    Standard input, output and error are sockets that are set to non-blocking, so a coroutine waiting for the child does not block the others. Use Process::run() instead of constructing it. The signal methods are shortcuts for sendSignal().

    phasync::run(function () {
    $process = phasync\Util\Process::run('sleep', ['10']);
    phasync::sleep(0.1);
    $process->sigterm();
});

    Defined in phasync\Util\ProcessRunner, package phasync/phasync.

    Methods

    • ProcessRunner::__construct Starts the process.
    • ProcessRunner::getStream Returns the stream of a standard descriptor.
    • ProcessRunner::stop Ends the process: SIGTERM, then SIGKILL after one second, and waits up to five seconds in all.
    • ProcessRunner::isRunning Returns true if the process is running.
    • ProcessRunner::isStopped Returns true if the process is paused by a stop signal.
    • ProcessRunner::getExitCode Returns the exit code of the process, or false while it runs.
    • ProcessRunner::sendSignal Sends a signal to the process, and returns false without sending it if the process is not running.
    • ProcessRunner::sigterm Sends SIGTERM, which a process can catch to shut down.
    • ProcessRunner::sigkill Sends SIGKILL, which a process cannot catch or ignore.
    • ProcessRunner::sigint Sends SIGINT, the signal of Ctrl+C.
    • ProcessRunner::sigstop Sends SIGSTOP, which pauses the process until sigcont().
    • ProcessRunner::sigcont Sends SIGCONT, which resumes a process paused by sigstop().
    • ProcessRunner::sighup Sends SIGHUP, which many daemons take as a request to reload their configuration.
    • ProcessRunner::read Waits until the stream has something to read, and returns what is there; an empty string at the end of the stream.
    • ProcessRunner::write Waits until the stream can take data, and writes as much as it takes; false if the process is not running.

    See also

    • Process::run Starts $command in the background and returns the object that controls it.
    • ProcessInterface A child process started with Process::run(), with its standard streams usable from coroutines.
